## The Problem

The client's team was tracking business metrics in a Google Sheet that took 20 minutes to refresh. The data came from multiple sources — a PostgreSQL database, a third-party API, and manual CSV uploads. Every morning, someone spent an hour copying data between sources.

The founder wanted a real-time dashboard that any team member could check without asking an analyst. The existing spreadsheet was error-prone and impossible to share without giving full access.

## The Approach

I designed a WebSocket-based architecture. The backend connected to all data sources, normalized the data, and pushed updates to connected clients in real time. When new data arrived, every connected user saw it within 2 seconds.

On the frontend, I built reusable D3.js chart components — line charts, bar charts, and a custom heatmap. Each component accepted data props and handled its own transitions. The charts animated smoothly when data updated, making changes easy to notice.

For the large dataset (some tables had 100k+ rows), I implemented virtual scrolling — only rendering the visible rows. This kept the UI responsive even with massive datasets.

## The Result

Data refresh time dropped from 20 minutes to 2 seconds. The team stopped checking the spreadsheet entirely. Within a month, the dashboard was the first thing the team opened every morning. The founder reported that decisions were being made faster because the data was always current.
